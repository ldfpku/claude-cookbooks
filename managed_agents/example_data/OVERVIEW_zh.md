# 示例数据

本目录存放 cookbook 笔记本读取的小型自包含输入。这里的所有文件都已入库，因此你可以端到端运行 cookbook，无需搭建数据库、注册 API，也无需在 `ANTHROPIC_API_KEY` 之外配置任何凭据。每个子目录与一个笔记本配对，且只有该笔记本会使用它。

这些测试数据刻意做得很小。它们的规模适合人在几分钟内读完，小到你可以自己打开文件、跟随智能体的推理思路，同时又大到确有值得分析的内容。每个数据集都至少埋了一个小陷阱或波折：两个缺陷之间的依赖关系、与代码不一致的过时文档文件、正好卡在审批阈值边缘的收据。目的是给智能体真正需要攻克的题目，而不是首次尝试必定成功的玩具。

| 目录 | 使用方 | 笔记本重点 | 内容 | 大致运行时间 |
|-----------|---------|----------------|---------------|-----------------|
| `iterate/` | `CMA_iterate_fix_failing_tests.py` | 在失败的测试套件上做“执行 → 观察 → 修复”循环 | 一个小型 `calc.py` 包，内含三个埋入的缺陷和对应的测试文件。其中一个失败是另一个的下游结果，因此细心的智能体会修复根因，然后看到第二个测试自行通过。| 约 2 分钟 |
| `orchestrate/` | `CMA_orchestrate_issue_to_pr.py` | 通过模拟的 `gh` CLI 把一个 issue 一路推进到合并的 PR | 一个在 `.gh-state/` 中持久化状态的模拟 `gh` 脚本，一个描述模糊 Unicode 缺陷的 `issue_42.json`，以及一个埋有缺陷的小型 `src/` 加 `tests/` 仓库。这条链路迫使智能体在过程中从 CI 失败中恢复，并处理评审机器人提出的文档字符串细节问题，然后才能合并。| 约 5 分钟 |
| `gate/` | `CMA_gate_human_in_the_loop.py` | 使用自定义工具实现人在环路的审批通道 | 一个描述审批规则的 `policy.yaml`，以及十二张覆盖政策每个分支的收据：干净通过、干净拒绝，以及几个真正模糊、智能体应上报而非自行猜测的案例。| 约 3 分钟 |
| `mongodb_on_cma/` | `CMA_with_mongodb_atlas.ipynb` | 用 MongoDB Atlas 检索为欺诈审查智能体提供依据 | `seed_transactions.jsonl`：20 条欺诈审查交易，每行带有预先计算的 1024 维嵌入向量。五条通道（干净通过、明确拒绝、结构化、高价值、欺诈团伙），使混合检索和图遍历各有真实可挖掘的内容，另外还有智能体应上报而非自动裁决的边界案例。| 约 4 分钟 |

第四个笔记本 `CMA_explore_unfamiliar_codebase.py` 同样基于测试数据运行，但它的仓库夹具足够小，由 `utilities.make_unfamiliar_repo_zip()` 在内存中生成，而不必入库。这个辅助函数比一堆存根文件目录更短更易读，并把陷阱（一份描述旧单体架构、已与真实微服务代码不符的过时 `ARCHITECTURE.md`）放在一个显眼的位置。

本目录中的所有内容都离线运行。模拟 CLI 读写本地 JSON 而不发起网络调用，测试运行器只是 `python3 -c` 调用，这里没有任何东西会向外发送数据。
