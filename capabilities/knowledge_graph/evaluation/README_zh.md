# 知识图谱抽取评估

针对 `../data/sample_triples.json` 中人工标注的金标准数据集，对实体和关系抽取进行打分。

## 运行

在仓库根目录安装依赖并设置 API 密钥：

```bash
uv sync --all-extras
cp .env.example .env  # then edit .env to add ANTHROPIC_API_KEY
```

然后：

```bash
uv run python capabilities/knowledge_graph/evaluation/eval_extraction.py
```

## 指标

**实体 P/R/F1** —— 若某个抽取出的实体经规范化后的名称与同一文档中的金标准实体一致，则计为真阳性。规范化会转为小写，并通过 `data/alias_map.json` 把已知的表面形式变体（“National Aeronautics and Space Administration” → “nasa”）映射到标准名称。

**关系 P/R/F1** —— 若某条关系两个规范化后的端点都与金标准的（源，目标）配对相符，则计为真阳性。**谓词措辞被忽略**：“commanded” 和 “was commander of” 都算数，但同样两个实体之间语义错误的谓词如 “destroyed” 也会算数。这使得所报告的关系召回率成为一个上界——它衡量的是抽取器是否找到了正确的*连接*，而不在于是否标注正确。若要更严格的打分，可加入谓词相似度检查（例如对每个候选配对调用一次 Claude 评判）。

## 预期基线

使用 `claude-haiku-4-5` 和指南中的抽取提示词，预期结果大致为：

| 指标 | P | R | F1 |
|---|---|---|---|
| 实体 | 0.80–0.90 | 0.70–0.85 | 0.75–0.85 |
| 关系 | 0.70–0.85 | 0.55–0.70 | 0.60–0.75 |

这些区间仅供参考；由于模型的不确定性，实际得分每次运行都会有波动。

关系召回率是那个较难的数字——抽取器往往比较保守，宁少而精，倾向于给出较少的高置信度边，而不是穷尽式的覆盖。若把抽取提示词调向更高的召回率（例如“抽取所有陈述过的关系，哪怕次要的关系”），就会以精确率换取召回率。
